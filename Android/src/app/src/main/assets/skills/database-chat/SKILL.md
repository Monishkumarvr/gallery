# Database Chat

## Instructions

Use this skill when the user asks questions about production, foundry, Postgres, MongoDB, analytics, trends, counts, heats, castings, energy, safety, AGNI, POURING, or other database-backed business data.

The local on-device model is the reasoning agent. The backend is only a read-only tool gateway. Never ask the backend to generate an answer. Never send database credentials.

### Agent selection

- Use `postgres` for foundry production schema questions such as heats, castings, energy readings, breakdowns, inventory, furnaces, ladles, grades, tests, customers, users, shifts, or QuerySpec questions.
- Use `mongo` for MongoDB dataset questions, company/module questions, safety/PPE/helmet data, AGNI, POURING, or questions that mention Hicon, TRSL, YMPL, Yash Metallics, or Unimech.
- If the user explicitly names Postgres or MongoDB, use that agent.
- If unclear, default to `postgres` and state the assumption briefly in the final answer.

### Required flow

1. Call `run_js` with:
   - `skillName`: `database-chat`
   - `scriptName`: `index.html`
   - `data`: `{"action":"schema","agent":"postgres"}` or `{"action":"schema","agent":"mongo"}`
2. Use the returned schema/tool context to build a read-only request.
3. Call `run_js` again with:
   - `data`:
     ```json
     {
       "action": "query",
       "agent": "postgres",
       "request": { "type": "queryspec", "payload": {} }
     }
     ```
     or:
     ```json
     {
       "action": "query",
       "agent": "mongo",
       "request": {
         "type": "mongoTool",
         "payload": {
           "tool": "find",
           "arguments": { "database": "agniss_db", "collection": "...", "filter": {}, "limit": 25 }
         }
       }
     }
     ```
4. Summarize the returned raw result locally. Include relevant counts, rows, trends, and warnings.

### Postgres request rules

- Use only QuerySpec JSON. Do not send SQL strings.
- Allowed QuerySpec actions include `count`, `list`, `aggregate`, `timeseries`, `correlate`, and `join` if the schema supports them.
- Keep result limits small unless the user asks otherwise.
- If you cannot confidently build a QuerySpec from the schema, explain what is missing instead of guessing.

### Mongo request rules

- Use only allowed read-only tools: `list-collections`, `collection-schema`, `collection-indexes`, `collection-storage-size`, `db-stats`, `explain`, `find`, `aggregate`, and `count`.
- Always use database `agniss_db`.
- Never use write stages or operations such as `$out`, `$merge`, insert, update, delete, drop, or rename.
- For `find`, include a limit of 25 unless the user asks for a smaller or larger bounded result.
- For `aggregate`, use read-only stages only.

### Output rules

- Answer in concise business language.
- Do not expose backend tokens, gateway URL, or database credentials.
- Do not claim the data was generated by the backend model; the local model is doing the reasoning.
- If the gateway is unavailable or rejects a request, report the reason and suggest what to check.
